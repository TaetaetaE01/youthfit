# `create-pr` 스킬에 `/cr` 셀프 리뷰 선행 단계 통합 설계

- 작성일: 2026-05-14
- 상태: Draft
- 범위: `.claude/skills/create-pr/SKILL.md` 한 파일 변경

## 1. 배경

이전 작업(PR #99)으로 `/cr [base]` 셀프 리뷰 슬래시 커맨드와 `code-reviewer` 서브에이전트가 추가됐다. 그러나 `/cr` 은 **수동 트리거** 라 사용자가 PR 생성 직전에 직접 입력해야 한다. 사용자 의도("자동 트리거 되는 게 자연스럽다")를 반영하되, 슬래시 커맨드 자동화는 hook 부담이 크므로 **`create-pr` 스킬의 절차에 선행 단계로 끼워넣는** 방식이 가장 자연스러운 접점이다.

## 2. 결정 사항

| 항목 | 결정 |
|---|---|
| 변경 위치 | `create-pr/SKILL.md` "## PR 작성 절차" 의 1번 단계 앞에 **0번** 추가 |
| 분기 — Critical | PR 생성 **중단**. 리포트 표시 + 수정 안내 |
| 분기 — Major | 리포트 표시 + 사용자 확인 한 줄. 진행 의사 있을 때만 다음 단계 |
| 분기 — Minor / 없음 | 리포트 표시 후 곧바로 1단계 진행 |
| 리포트 위치 | 콘솔에만 출력. PR 본문에 포함하지 않음 |
| `code-reviewer.md` / `cr.md` | 수정하지 않음 — `create-pr` 가 호출자 역할만 |

.claude/skills/create-pr/SKILL.md   (수정)

## 4. SKILL.md 에 들어갈 신규 0번 단계 본문

기존 "## PR 작성 절차" 섹션의 1번 단계 바로 위, 또는 별도 하위 섹션 "### 0. 셀프 리뷰 선행" 으로 다음 내용을 삽입한다.

````markdown
0. **`/cr` 셀프 리뷰 선행**

   PR 본문을 작성하기 전에 `/cr` 슬래시 커맨드를 호출해 현재 브랜치를 base(보통 `main`) 와 비교한 셀프 리뷰 리포트를 받는다. base 결정은 `/cr` 자체가 수행하므로 별도 인자 없이 호출해도 된다.

   리포트의 **Verdict** 에 따라 분기:

   - 🔴 **Critical (>0)** — PR 생성을 **중단**한다. 리포트를 그대로 사용자에게 보여주고, 한 줄로 안내한다:
     > "Critical 이슈가 있어 PR 생성을 중단했습니다. 수정 후 다시 PR 생성을 요청해 주세요."

     이후 단계로 진행하지 않는다.

   - 🟡 **Major (>0, Critical=0)** — 리포트를 그대로 보여주고 명시적 확인을 받는다:
     > "Major 이슈가 N건 있습니다. 그대로 PR 을 생성할까요?"

     사용자가 "예 / yes / 진행" 류로 답하면 1단계로 진행. "아니오 / 수정 / no" 류면 중단.

   - 🟢 **Critical=0, Major=0** — 리포트를 보여주고 별도 확인 없이 곧바로 1단계로 진행한다.

   리포트는 **콘솔에만** 출력한다. PR 본문에는 포함하지 않는다.
````

## 5. 단계 번호 매김

기존 1~7번 단계를 그대로 두고 신규 단계는 **0번** 으로 추가한다. 이유:
- 기존 단계 번호를 깨면 다른 곳에서 "절차 3번 참조" 같이 참조하는 내용과 어긋남
- 0 이 "준비/사전 검증" 의미로 자연스러움
- 미래에 셀프 리뷰가 빠지더라도 1~7 은 그대로 살아남음

## 6. 사용자 경험 흐름

```
User: "PR 만들어줘"
  ↓
create-pr 스킬 트리거
  ↓
0. /cr 호출
  ├── Critical → 중단 + 안내
  ├── Major → 사용자 확인 → (예) 진행 / (아니오) 중단
  └── 깨끗 → 그대로 진행
  ↓
1. git diff main...HEAD
  ↓
... (기존 2-7 단계)
  ↓
gh pr create
```

## 7. 스코프 — 명시적 제외

- `/cr` 결과를 PR description 자동 삽입 (콘솔만)
- Major 자동 차단 (사용자 확인 후 진행 가능)
- Minor 도 사용자에게 확인 받기 (소음 증가)
- `/review`, `/security-review`, `/ultrareview` 등 다른 리뷰 커맨드와의 연동
- `/cr` 슬래시 커맨드나 `code-reviewer` 서브에이전트 자체 수정 — 이번 변경은 *호출자만* 손본다
- hook 자동 트리거 (PostToolUse, Stop, pre-push) — 여전히 스코프 외

## 8. 검증

이 변경은 SKILL.md 마크다운 문서 1개를 수정하므로 단위 테스트 대상이 아니다. 수동 스모크:

1. 우리 PR (#99) 같은 작은 브랜치에서 "PR 만들어줘" → `/cr` 이 먼저 호출되는지, 깨끗하면 그대로 PR 생성으로 진행되는지.
2. 의도적으로 Critical 위반 1줄을 임시 브랜치에 도입 → "Critical 이슈가 있어 PR 생성을 중단했습니다" 안내가 나오고 `gh pr create` 가 실행되지 않는지.
3. Major 케이스: 컨벤션 위반 1줄로 Major 만 발생 → 사용자 확인 prompt 가 떠야 하고, "예" 라고 답해야만 PR 생성으로 넘어가는지.
